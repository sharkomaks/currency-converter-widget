# The overlay is automatic — there is no button and no gate

Status: proposed

The user rejected every gate on automatic triggering in one word — «100% автоматически»: no toolbar button, no
keyboard shortcut, no "convert" confirmation. The overlay appears when a selection is an exact amount
expression and disappears with the selection.

**The decision is settled; the reason is still owed.** It has been asked for twice in plain prose and not yet
answered, and it must not be invented here. Three candidate rationales, to be chosen from, combined, or
corrected:

1. **Zero learning cost.** A trigger is a thing to discover, remember and explain; the product's whole promise
   is that selecting an amount already is the request.
2. **A confirmation gate fails silently.** A person who does not know about the shortcut concludes the
   extension is broken, and a silent no is worse than a wrong number nobody asked for.
3. **Value must arrive before any setup.** No activation, no configuration, no onboarding dependency — the
   first selection after install already works.

## Known cost

Overlays on selections nobody wanted converted: a price inside a paragraph selected while reading. Mitigated by
the exact-selection rule (`0011`) and by the overlay being transient, not by asking the person first.

## If this is ever revisited

The rejected shapes were: a toolbar button per conversion; a modifier key on selection; a small "→" chip next to
the selection that must be clicked. All of them keep the number behind a second gesture. Any of them changes
the product, not the implementation, so it needs the user, not an engineer.
