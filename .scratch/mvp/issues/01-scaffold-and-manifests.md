# 01 — Каркас сборки и манифесты

**What to build:** пустое расширение, которое реально ставится. Репозиторий получает каркас (bun,
tsconfig, два прохода Vite: контент-скрипт `iife` с фиксированным именем файла, остальное `esm` плюс
html), два статических манифеста (расхождение только в `background`), иконки, полную таблицу полей
манифеста (включая `action.default_popup`, `default_locale: "en"`, `version`) и проверку равенства
манифестов на сборке. Линт и форматирование — `oxlint` + `oxfmt`; красный линт = красная сборка.
Приложение открывается из тулбара и показывает заглушку.

**Blocked by:** None — can start immediately.

**Status:** done — Chrome проверен, Firefox за человеком

- [x] `bun run build` зелёный, и сборка валится при расхождении манифестов и при красном линте
- [x] Распакованная папка ставится в Chrome (режим разработчика) и открывает приложение — проверено
      в Chromium 140 распакованной папкой `dist/chrome`
- [ ] То же расширение ставится временным дополнением в Firefox — `web-ext lint` 0/0, загрузка
      временного дополнения остаётся ручной проверкой
- [x] В манифесте нет ничего сверх `storage` и `host_permissions` на Frankfurter
- [x] Проверка равенства манифестов игнорирует ровно `background` и `browser_specific_settings`

Статус: код готов; сборка зелёная. При установке в Chrome всплыла реальная находка: ключи
`messages.json` с точками Chrome отвергает и расширение не загружает — словари переведены на
`[A-Za-z0-9_]`, `t()` отображает точки в подчёркивания, тест на алфавит добавлен. Пути `assets` в
html теперь чинятся и для `href` (CSS страниц ранее оставался со `../../assets`).
